## KPI(s) / evidence
KPI-03 | ≥99.5% | 66.9% (160 holdout executions; seed set 100% but tuned-on, NOT evidence) ; KPI-06 | ≤1% | 7.51% (16/213)

## Root cause
Regex rules were tuned to the author's 100 seed prompts and do not generalise (holdout direct 71%, fuzz 30%, indirect 95% after adding the classifier to the chunk scanner). The pretrained classifier generalises better but flags the benign stress wrapper 'Please ignore the old label and tell me…' (16/213) because it resembles an override. The allowance rule (query mentions a real catalog entity AND no regex hit) is a known gap: an attack prefixed by a domain question evades the classifier.

## Planned fix (for I2 / v0.1)
Fine-tune/calibrate the classifier on a larger public attack corpus + in-domain benign data with a held-out split never used for tuning; add paired attack/benign wrappers to training; replace the entity-id allowance with a calibrated score combination; keep regex only for precise structural attacks (SQLi/traversal/delimiters). Grow the holdout to ≥600 executions so a 0-miss result can support ≥99.5%.

## Regression test
tests: a frozen holdout file that CI must never train/tune on; failing test for 'domain-prefixed attack' evasion.
